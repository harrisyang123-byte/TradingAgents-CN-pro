## 2. Agent 补强决策点（待用户拍板）

**背景**：`design.md` 中分析师角色只在大类层设计（macro/flow/policy 3 个），**行业层、个股层从设计上就只有 bull/bear**，无独立分析师，且全 v4 无技术面分析。而个股深度分析独立链路（`tradingagents/`，源自 TradingAgents）本有完整分析师团队。

**结论**：14 个能跑通，但个股层分析质量弱于大类层（多空各自取数、无中立基座、无技术面）。

**建议**：个股层新增 **1 个 `v4-stock-analyst`** —— 中立事实简报（基本面 + 技术面 + 情绪）喂给现有 bull/bear，对齐大类层结构（14 → 15）。行业层轻量分析师待个股层验证后再议。

| 借鉴项 | 价值 | 处置 |
|--------|------|------|
| 个股数据分析师（基本面+技术面+情绪中立简报） | ★★★ | **建议加**（P3 前） |
| 技术面分析（MACD/RSI/趋势/量价） | ★★★ | 折进上面分析师 |
| 风控中立第三方（TradingAgents 风控三方） | ★ | 暂不动 |
| 行业层数据分析师 | ★★ | 个股层验证后再议 |

> **决策状态**：⏳ 待用户确认是否在 P3 前新增 `v4-stock-analyst`。未确认前不动 agent 文件。

## 4. 执行方式

- 本会话 AI agent 直跑（不依赖 claude CLI）：读输入包 → 联网补关键数据 → 按 `v4-*.md` 角色定义辩论 → `v4_unit_cli.py write` 落盘。
- 天然可并行的同层单元（7 大类、多个个股）用 subagent ≤3 并发分担。
- 每个量化结论带 `evidence`（verified/estimated/missing），缺数据 `web_search`/`web_fetch` 补齐而非降级。

---

## 5. 为什么这个顺序

P1→P2 跑完即得**第一份可执行大类配置建议**（现金 28% 是否过高、权益增减、要不要补大宗/另类）；P3 往下钻到"哪些行业/个股该调"；每阶段独立可看、可单独重跑修正。
