# ace-generate

从 `domain.yaml` 生成项目配置和生命周期脚本。在项目目录（`domains/<project>/`）下运行。

## 前置检查

```bash
test -f domain.yaml || { echo "错误：当前目录无 domain.yaml，请在 domains/<project>/ 下运行"; exit 1; }
```

## 执行流程

1. 读取 `domain.yaml` 全部内容（`name`、`tech_stack`、`services`、`lifecycle`、`scripts`、`coding_standards`、`testing`、`knowledge`）
2. 生成 `CLAUDE.md`（覆盖已有）
3. 如果 `services` 段存在：
   - 生成 `start.sh`、`stop.sh`、`status.sh`（覆盖已有，`chmod +x`）
   - 生成 `.gitignore`（追加缺失条目，不覆盖已有）
4. 如果 `services` 段不存在：跳过脚本生成，提示用户补充

---

## CLAUDE.md 模板

生成的 CLAUDE.md 必须包含以下段落，按顺序排列：

```markdown
<!-- Generated by ACE Engine | DO NOT EDIT | Run: /ace-generate -->

# {name} — AI 协作指令

## 开发工作流

当用户提出功能需求时，遵循 ACE 工作流。简单改动（格式、拼写、单行配置）可直接修改。

```
planner → applier → reviewer → archiver → retro
旁路：investigator
```

每个阶段通过对应的 ace-* skill 执行，禁止跳过。
```

## start.sh 模板

适用于 hybrid 模式（数据库在 Docker，前后端本地 dev server）。

从 `domain.yaml` 读取 `services` 和 `lifecycle` 生成，包含以下部分：

### 头部

```bash
#!/bin/bash

# {name} - 一键启动脚本（配置驱动）
# 从 domain.yaml 读取服务配置，按依赖拓扑启动

set -e

SCRIPT_DIR="$( cd "$( dirname "${BASH_SOURCE[0]}" )" && pwd )"
DOMAIN_YAML="$SCRIPT_DIR/domain.yaml"
PID_DIR="$SCRIPT_DIR/{lifecycle.pid_dir 或 .pids}"
LOG_DIR="$SCRIPT_DIR/{lifecycle.log_dir 或 .logs}"

mkdir -p "$PID_DIR" "$LOG_DIR"
```

### YAML 轻量解析函数（verbatim，所有项目相同）

```bash
parse_port() {
  local service="$1"
  grep -A5 "^  ${service}:" "$DOMAIN_YAML" 2>/dev/null | grep "port:" | head -1 | sed 's/.*port:\s*//' | tr -d ' '
}

parse_health_path() {
  grep -A3 "health_check:" "$DOMAIN_YAML" 2>/dev/null | grep "backend:" | head -1 | sed 's/.*backend:\s*//' | tr -d ' "'
}

parse_health_timeout() {
  grep -A3 "health_check:" "$DOMAIN_YAML" 2>/dev/null | grep "timeout:" | head -1 | sed 's/.*timeout:\s*//' | tr -d ' '
}

parse_db_container() {
  grep "container_name:" "$SCRIPT_DIR/docker-compose.yml" 2>/dev/null | head -1 | sed 's/.*container_name:\s*//' | tr -d ' '
}
```

### 健康检查函数（verbatim，所有项目相同）

```bash
wait_for_url() {
  local url="$1"
  local max_wait="$2"
  local label="$3"
  local elapsed=0
  while [ $elapsed -lt "$max_wait" ]; do
    if curl -s "$url" > /dev/null 2>&1; then
      return 0
    fi
    sleep 2
    elapsed=$((elapsed + 2))
  done
  echo "  ❌ ${label} 在 ${max_wait}s 内未就绪"
  return 1
}

wait_for_db() {
  local max_wait="$1"
  local elapsed=0
  while [ $elapsed -lt "$max_wait" ]; do
    local status
    status=$(docker inspect --format='{{.State.Health.Status}}' "$DB_CONTAINER" 2>/dev/null || echo "missing")
    if [ "$status" = "healthy" ]; then
      return 0
    fi
    sleep 2
    elapsed=$((elapsed + 2))
  done
  echo "  ❌ 数据库在 ${max_wait}s 内未就绪"
  return 1
}

is_running() {
  local port="$1"
  curl -s "http://localhost:${port}" > /dev/null 2>&1
}
```

### 配置读取

为 `services` 中的每个服务读取端口，设置兜底默认值：

```bash
{SERVICE}_PORT=$(parse_port "{service_name}")
: "${{SERVICE}_PORT:={默认端口}}"
```

数据库端口默认值：postgresql=5432, mysql=3306。Backend 默认 3000，Frontend 默认 5173。

### 服务启动段（按依赖拓扑生成）

按 `services.*.dependencies` 字段排序：无依赖的服务最先启动，依赖已处理的服务接着启动。每个服务生成一个编号段落。

**对于 database 类型的服务**（有 `type` 字段）：

```bash
echo "{N}️⃣  数据库 (port: ${DB_PORT})..."

if ! docker ps > /dev/null 2>&1; then
  echo "  ❌ Docker 未运行，请先启动 Docker Desktop"
  exit 1
fi

cd "$SCRIPT_DIR"
docker compose up -d > /dev/null 2>&1
echo "  ⏳ 等待数据库就绪..."

if wait_for_db "$HEALTH_TIMEOUT"; then
  echo "  ✅ 数据库就绪"
else
  exit 1
fi
```

**对于 backend 服务**（`tech_stack.backend` 含 "prisma" 时包含迁移）：

```bash
echo "{N}️⃣  后端 (port: ${BACKEND_PORT})..."

cd "$SCRIPT_DIR/backend"

if [ ! -d "node_modules" ]; then
  echo "  📦 安装依赖..."
  npm install > /dev/null 2>&1
fi

# 仅当 tech_stack.backend 含 "prisma" 时生成以下 3 行：
echo "  🔄 数据库迁移..."
npx prisma migrate deploy > /dev/null 2>&1 || npx prisma migrate dev --name init > /dev/null 2>&1
# Prisma 段结束

if is_running "$BACKEND_PORT"; then
  echo "  ✅ 后端已在运行"
else
  echo "  🚀 启动后端..."
  npm run dev > "$LOG_DIR/backend.log" 2>&1 &
  BACKEND_PID=$!
  echo "$BACKEND_PID" > "$PID_DIR/backend.pid"

  if wait_for_url "http://localhost:${BACKEND_PORT}${HEALTH_PATH}" "$HEALTH_TIMEOUT" "后端"; then
    echo "  ✅ 后端就绪 (PID: ${BACKEND_PID})"
  else
    exit 1
  fi
fi
```

**对于 frontend 服务**：

```bash
echo "{N}️⃣  前端 (port: ${FRONTEND_PORT})..."

cd "$SCRIPT_DIR/frontend"

if [ ! -d "node_modules" ]; then
  echo "  📦 安装依赖..."
  npm install > /dev/null 2>&1
fi

if is_running "$FRONTEND_PORT"; then
  echo "  ✅ 前端已在运行"
else
  echo "  🚀 启动前端..."
  npm run dev > "$LOG_DIR/frontend.log" 2>&1 &
  FRONTEND_PID=$!
  echo "$FRONTEND_PID" > "$PID_DIR/frontend.pid"

  if wait_for_url "http://localhost:${FRONTEND_PORT}" "$HEALTH_TIMEOUT" "前端"; then
    echo "  ✅ 前端就绪 (PID: ${FRONTEND_PID})"
  else
    exit 1
  fi
fi
```

**边界情况**：
- 无 database 服务 → 跳过 Docker 检测、`docker compose up`、`wait_for_db`
- 无 frontend 服务 → 跳过 frontend 段
- `tech_stack.backend` 不含 "prisma" → 跳过迁移/seed 命令

### 完成输出

列出所有服务的访问地址和日志路径。

## stop.sh 模板

### 头部

```bash
#!/bin/bash

# {name} - 停止脚本（配置驱动）
# 从 domain.yaml 读取服务配置，反序停止

set +e
```

**关键**：必须 `set +e`，不能 `set -e`，因为 kill 命令经常返回非零值。

### 函数

包含与 start.sh 相同的 `parse_port` 和 `parse_db_container`。

**stop_service 函数**（verbatim，所有项目相同）：

```bash
stop_service() {
  local name="$1"
  local port="$2"
  local pid_file="$PID_DIR/${name}.pid"
  local had_something=false

  # 1. 端口清扫：先杀掉真正占端口的进程（tsx/vite 子进程）
  if [ -n "$port" ]; then
    local port_pids
    port_pids=$(lsof -ti :"$port" 2>/dev/null || true)
    if [ -n "$port_pids" ]; then
      echo "$port_pids" | xargs kill 2>/dev/null || true
      sleep 1
      port_pids=$(lsof -ti :"$port" 2>/dev/null || true)
      if [ -n "$port_pids" ]; then
        echo "$port_pids" | xargs kill -9 2>/dev/null || true
      fi
      had_something=true
    fi
  fi

  # 2. PID 清理：杀掉可能存活的 npm 父进程
  if [ -f "$pid_file" ]; then
    local pid
    pid=$(cat "$pid_file")
    if kill -0 "$pid" 2>/dev/null; then
      kill -9 "$pid" 2>/dev/null || true
      had_something=true
    fi
    rm -f "$pid_file"
    [ "$had_something" = false ] && had_something=true
  fi

  if [ "$had_something" = true ]; then
    echo "  ✓ ${name} 已关闭"
  else
    echo "  - ${name} 未运行"
  fi
}
```

### 停止顺序

按依赖拓扑的**逆序**停止。对于标准三服务项目：frontend → backend → database。

非 database 服务调用 `stop_service`，database 服务用 `docker compose down`。

**关键提醒**：每个 `local` 只赋一个变量，避免 bash local 陷阱。

## status.sh 模板

### 函数

```bash
check_service() {
  local name="$1"
  local port="$2"
  local pid_file="$PID_DIR/${name}.pid"
  local status="DOWN"
  local pid_info=""

  if curl -s "http://localhost:${port}" > /dev/null 2>&1; then
    status="UP"
  fi

  if [ -f "$pid_file" ]; then
    local saved_pid
    saved_pid=$(cat "$pid_file")
    if kill -0 "$saved_pid" 2>/dev/null; then
      pid_info="PID:${saved_pid}"
    else
      pid_info="PID:stale"
    fi
  fi

  printf "│ %-10s │ %5s │ %-4s │ %-10s │\n" "$name" "$port" "$status" "$pid_info"
}

check_db() {
  local status="DOWN"
  if docker ps --format '{{.Names}}' 2>/dev/null | grep -q "$DB_CONTAINER"; then
    local health
    health=$(docker inspect --format='{{.State.Health.Status}}' "$DB_CONTAINER" 2>/dev/null || echo "unknown")
    if [ "$health" = "healthy" ]; then
      status="UP"
    else
      status="$health"
    fi
  fi
  printf "│ %-10s │ %5s │ %-4s │ %-10s │\n" "database" "$DB_PORT" "$status" "$DB_CONTAINER"
}
```

### 输出

ASCII 表格，每个服务一行。表格行数根据 `services` 动态生成。

底部显示日志文件路径和启停命令提示。

**无 database 时**：不生成 `check_db` 函数，不输出 database 行。

## 注意事项

- 只生成上述段落/文件，不添加额外内容
- `domain.yaml` 中缺少 `services` 段 → 跳过脚本生成，只生成 CLAUDE.md
- `domain.yaml` 中缺少 `lifecycle` 段 → 脚本使用默认值（`.pids`、`.logs`、`/health`、30s）
- `tech_stack.backend` 不含 "prisma" → start.sh 跳过 Prisma 迁移/seed 命令
- scripts 段按前缀分组（dev:*、test:*、build:*、db:*）
- 三个脚本创建后执行 `chmod +x`
- 所有端口、路径、项目名必须从 domain.yaml 读取，不硬编码
- 每个 bash 函数中，每个 `local` 只赋一个变量（避免 bash local 陷阱）
- stop.sh 必须 `set +e`，start.sh 必须 `set -e`
- stop_service 必须端口清扫优先（处理 npm 进程树）
- 覆盖已有脚本（幂等），.gitignore 追加模式
- 生成完成后提示用户检查
