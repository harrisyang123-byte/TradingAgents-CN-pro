# 完整架构总览（修正版）

## 核心原则

**辩论是本系统的核心价值。** 一个 LLM 输出 → 另一个 LLM 挑战 → 再回答 → 再质疑 → 裁判裁决。不是数据收集 → LLM → 输出。

每个 L 层的辩论结构必须清晰：几人参加、几轮、谁裁判。每层的目标是：让用户看到"有人挑战过这个结论"。

## 市场温度计：情绪与黑天鹅——不是新 Agent，是渗进每个 Agent 的血液

```
决策 = 基本面 × 估值 × 情绪 × 风险

  基本面: Tier1 + L2 Scout 的数据引用 → "这家公司好"
  估值: PE 分位 → "现在便宜/贵"
  情绪: 别人贪婪还是恐惧？→ "便宜的可能是价值陷阱，贵的可能有泡沫"
  风险: 黑天鹅可以触发吗？→ "如果现在进场，最坏能亏多少"
```

**为什么"情绪"必须渗入 Agent？**

价值投资的本质不是"找便宜的买"，是"在别人恐惧时买入，在别人贪婪时卖出"。PE 分位告诉你"便宜"，但不知道"为什么便宜"——是价值低估，还是市场在跑路？

如果 L1 策略师判了"通信设备 Go"，但北向资金连续 5 日净流出、该行业资金净流出、融资余额下降——这个 Go 就必须降级为"条件触发"。"行业是好，但现在别人都在跑，你不是抄底，你可能在接飞刀。"

**我们有什么情绪数据？**

| 数据 | 源 | 已有？ | 含义 |
|------|------|------|------|
| 北向资金净流入/流出 | AKShare `stock_hsgt_hist_em` | ✅ market_signals.py | 外资在买还是卖 |
| 行业资金流向 | AKShare `stock_sector_fund_flow_rank` | ✅ market_tools.py | 钱在往哪个行业流 |
| 市场涨跌比 | AKShare `stock_zh_a_spot_em` | ✅ market_signals.py | 今天是普涨还是普跌 |
| 涨停/跌停数 | AKShare `stock_zh_a_spot_em` | ✅ 从涨跌幅 >±9.5% 统计 | 极端贪婪/恐惧信号 |
| 融资融券余额 | AKShare `macro_china_market_margin_sh` | ✅ market_signals.py | 散户在用杠杆吗 |
| 个股千股千评 | AKShare `stock_comment_em` | ✅ market_signals.py | 散户对该股的情绪评分 |
| Google 新闻量 | Google News API | ❌ | 突发新闻事件 |
| VIX/恐慌指数 | — | ❌ | A 股没有直接对应，可用涨跌比替代 |

**情绪数据流向每个 Agent**

```
数据收集层 → market_temperature.json
                        │
          ┌─────────────┼─────────────┐
          ▼             ▼             ▼
        L1 策略师      L2 Scout      CIO
  行业情绪→Go/NoGo  个股情绪→评分  全市场水温→timing
  +情绪修正因子    ±信心度调节    +immediate/conditional
          │             │             │
          ▼             ▼             ▼
        L3 策略师    交叉验证      风险总监
  集中情绪偏离    情绪×基本面     黑天鹅触发
  检测一致性      矛盾标红        ←最坏情景
```

**情绪怎么影响 Agent 决策？——逆向，不是顺势**

```
价值投资的核心: 别人恐惧时买入，别人贪婪时卖出。
情绪信号 = 反向信号。恐慌加重置信度，亢奋降低置信度。
```

| Agent | 情绪注入 | 逆向影响 |
|-------|---------|---------|
| **L1 策略师** | 每个行业的资金流向 + 涨跌幅排名 + 北向方向 | 行业基本面好+市场恐慌=**最佳买点 → 置信度加 30%**。行业基本面好+市场亢奋=**可能估值泡沫 → 降级为等一等**。行业基本面差+市场恐慌=可能已定价，不宜跟风卖。 |
| **L2 Scout** | 个股千股千评评分 + 市场涨跌比 | PE 分位 20% + 散户极度悲观 = **真正的低估 → 不能错过**。PE 分位 20% + 散户看多 = 市场对它的乐观打折了安全边际。PE 分位 85% + 散户疯狂看多 = 最多应该是观察，不应该是推荐。 |
| **L3 策略师** | 组合级情绪一致性 | 分析师推的 5 只加仓全在市场资金流出的行业 + 全在 PE 低位 → **这是逆势机会，不是风险**——标注"市场在卖、数据在说买"。分析师推的 5 只加仓全在市场资金流入+PE 高位的行业 → 标注"市场在追涨 = 时机不当"。 |
| **交叉验证** | 情绪 vs 基本面 方向检测 | 新增: "北向 5 日净流出 + 分析师推买入 = **不是恐慌卖出——是逆向买入机会**。PE 历史低位+融资余额下降 = 极度恐慌=可能是市场底部=置信度加分。" 新增: "行业 PE 历史高位+融资余额升高 + 分析师推买入 = **市场在追涨 = 时机不良**。" |
| **CIO** | 全市场水温 (°C) | 水温 ≥ 80°C（亢奋）→ 处方 timing 倾向 `conditional` 或 `scheduled` **（不要在疯狂时追涨）**。水温 ≤ 30°C（极度恐慌）→ 处方 timing 倾向 `immediate` **（别人恐惧时你出手）**。水温中性 → 遵循 PE 分位的独立判断。 |
| **风险总监** | 黑天鹅触发检测 | 检测到黑天鹅 + 用户现金 ≥ 30% = **不是卖出——是等待——你已经有弹药了**。检测到黑天鹅 + 用户现金 ≤ 10% = **你满仓在恐慌中——这是危险，必须减仓腾出买入空间**。 |

**黑天鹅检测 —— 规则引擎，非 LLM**

```
触发条件（三条同时满足 = 高置信度黑天鹅预警）:
1. 市场涨跌比 < 25%（今天 3/4 的股票在跌）
2. 北向资金连续 ≥ 5 日净流出
3. 融资余额周变化 < -5%（杠杆资金在跑路）

预警升级:
- 如果用户重仓行业（>15%）同时触发行业级黑天鹅 → HIGH 级别
- 如果用户现金占比 > 40% → 不用太担心
- CIO 处方中加"黑天鹅预警：建议保持现金缓冲 ≥ 20%"段落

行业级黑天鹅:
- 单行业整体跌幅 > 10% + 该行业资金流出 > 5% + 融资余额下降
→ 如果用户有该行业敞口，在处方中标注"黑天鹅风险"
```

**为什么不需要新 Agent？**

情绪不是"新闻部"的独立职责——它是每个已有 Agent 的参数修正因子。加一个"新闻分析师"Agent 会导致信息割裂——L1 看不到 L_news 的结论，L_news 看不到 L1 的行业判断。每一个已有 Agent 应该直接消费情绪数据做决策，而不是等一个独立 Agent 汇总后再分发。

## 二、辩论结构总表

| 层级 | 参与Agent | 轮次 | 裁判 | 每轮发言顺序 | 移除的Agent |
|------|----------|------|------|------------|-----------|
| **L1 行业方向** | 策略师 ↔ 反向者 | max 2 | 宏观裁判 | 策略师→反向者→策略师→反向者→裁判 | — |
| **L2 标的筛选** | Scout (单次) | — | 6维评分+交叉验证 | Scout→交叉验证 | 反向者(被规则引擎+top_risks替代)、裁判(被评分映射替代) |
| **L3 组合构建** | 分析师 ↔ 策略师 | max 2 | 无(冲突交CIO裁决) | 分析师→策略师×N→CIO | 侦察兵(被"分析师+策略师"的组合缺口计算替代) |
| **L4 最终处方** | CIO初稿 ↔ 风险总监 | max 1 | CIO终裁 | CIO→风险→CIO终裁 | — |

### L2 辩论移除的详细理由（可证伪）

```
Scout 已输出: {total_score, valuation, top_risks}
交叉验证:    检查 PE 分位 vs total_score 的一致性 → 冲突报告

原反向者的价值:   "这只股票有风险吗？"
Scout 已经有了:  top_risks 字段列出 Top-3 风险

原裁判的价值:    "推荐还是淘汰？"
Scout 已经有了:  total_score >= 35 → 强烈推荐, 映射表已固定

→ 两个角色没有新增信息。去掉不会降低质量。
→ 证伪方式: 跑一次 E2E，对比 "Scout raw 6维评分 → CIO 直接消费" 和 "Scout → 反向者 → 裁判 → CIO" 两版。如果 CIO 处方质量评估无显著差异，则移除决策正确。
```

### L3 侦察兵移除的详细理由（可证伪）

```
原侦察兵角色: 发现组合缺口（如"缺新能源敞口"）
被替代方:    L1 裁判已输出超配/标配/低配方向 → 缺口从 L1 的"低配/零配"行业中自然得出
            分析师可以标注"组合在这个风格上缺失"
            策略师有集中度数据可以算哪些行业方向缺口

→ 侦察兵不需要独立 Agent —— 缺口逻辑已散布在 L1 和 L3 中
→ 证伪方式: 跑一次 E2E，看没有侦察兵时 CIO 是否能从 L1 方向+分析师覆盖中自行推断缺口
```

| G19: **没有全市场水温概念** | CIO 做 timing 决策时不考虑市场整体状态（恐慌/亢奋/中性） | HIGH | 需要 `market_temperature.json` 文件作为所有 Agent 的共享输入 |

| G21: **没有黑天鹅检测** | 系统没有"极端事件预警"能力。如果市场暴跌 10%，系统应该告诉用户"这是系统性恐慌，你的组合会受影响"——而不是让用户自己猜 | HIGH | 新增交叉验证规则 + 风险总监 prompt 增强 |

**→ 补什么**: G15 补前三层 → G16 补 CIO prompt → G17 补交叉验证层 → **G18-G21 补市场温度计**: `market_temperature.json` → 每个 Agent 的输入 + 黑天鹅检测规则 → 交叉验证 + 风险总监消费

**→ 补什么**: G15 补前三层 → G16 补 CIO prompt → G17 补交叉验证层

### Gap 汇总：21 个差距，16 个在 L1-L3，5 个在数据收集/情绪层

```
数据收集层: G10(Tier1匹配) · G11(industry) · G18(情绪数据未及Agent) = 3 gap

L1 行业方向:  G1(宏观) + G2(过浅) + G4(持仓视角) + G18b(情绪修正) = 4 gap
             · 修复: prompt + 输入视角 + 情绪修正

L2 标的筛选:  G5(财务引用) + G6(中小市值) + G7(价格区间) + G8(L1连接) + G9(缺口感知) = 5 gap
             · 修复: Scout 能力补全 + 情绪信心度调节

L3 组合构建:  G12(管道) + G13(一致性风险) = 2 gap
             · 修复: JSON 总线 + 策略师文本分析能力 + 情绪一致性检查

L4 最终处方:  G15(前三层汇总) + G16(资金来源) + G17(交叉验证) + G19(水温)+ G20(timing情绪)+ G21(黑天鹅) = 6 gap
             · 修复: 前三层补完后自然好转 + 交叉验证 + 市场温度计 + 黑天鹅规则
```

## 五、Agent 目的验证：为什么这个 Agent 必须存在？

**评估框架**：每个 Agent 必须满足以下至少三项中的两项：
- **不可替代性**：有没有其他 Agent 或机制能做同样的事？
- **专有信息**：是否拥有其他 Agent 看不到的独特输入数据或视角？
- **决策杠杆**：产出是否直接影响最终处方？

**判定结果**：
- ✅ = 保留：三项全满足
- ⚠️ = 审慎保留：满足两项，但有一个弱项
- ❌ = 移除：不满足两项

---

#### L1 行业方向

| Agent | 不可替代性 | 专有信息 | 决策杠杆 | 判定 | 分析 |
|-------|----------|---------|---------|------|------|
| **策略师** | ✅ 唯一看多视角来源 | ✅ 唯一读宏观数据+行业排名的角色 | ✅ 直接决定裁判的Go/NoGo基线 | ✅ | **必须存在**。如果移除，裁判将没有看多论据。当前问题不是"要不要"，是"它输出质量不够"——这是 prompt 和数据注入的问题，不是角色冗余 |
| **反向者** | ⚠️ 不是唯一的质疑者。L2也有独立的焦点，L4的风险总监也能挑战 | ✅ 唯一读策略师输出+独立调工具验证数据 | ⚠️ 间接影响——裁判可以选择无视反向者 | ⚠️ | **审慎保留**。它的价值不在数据，在**迫使策略师回到工具中验证观点**。反向者说"你这个行业 PE 中位数不对，重新看数据"→策略师第二轮必须回应。这比裁判直接判更有说服力。但如果只有 2 轮辩论，反向者的边际价值在第 2 轮就降低了 |
| **裁判** | ✅ 唯一裁定角色 | ❌ 不读新数据，只看辩论记录 | ✅ 直接决定 Go/NoGo/超配/低配 | ⚠️ | **审慎保留**。裁判是必要的——但没有工具调用能力，只能基于策略师和反向者的辩论做判断。这意味着裁判的质量完全取决于前两者的输出质量。如果前两者都烂，裁判也烂 |

**L1 诊断**：三个角色没有冗余。瓶颈在策略师的数据摄入不够丰富。

#### L2 标的筛选

| Agent | 不可替代性 | 专有信息 | 决策杠杆 | 判定 | 分析 |
|-------|----------|---------|---------|------|------|
| **Scout** | ✅ 唯一调 6 个工具搜标的角色 | ✅ 看到行业成分股+公司概况+财务摘要 | ✅ 候选池直接进入 CIO 处方 | ✅ | **必须存在**。Scout 是 L2 的核心——没有它就没有候选池。当前问题不是角色冗余，是它没收到 L1 的 Go 行业指令 |
| **反向者** | ❌ Scout 已输出 top_risks。交叉验证已检查 PE 分位。反向者的质疑目标和这两者高度重叠 | ❌ 和 Scout 看一样的数据（同 6 个工具） | ❌ 裁判可以选择无视 | ❌ | **建议移除**。理由：(1) Scout 的 6 维评分模板已包含 `top_risks` 字段——这是自带的挑战。(2) 交叉验证规则引擎能精确发现 PE 分位 vs 评分的矛盾——这比 LLM 质疑更可靠。(3) 反向者和 Scout 共享同一套工具和数据源，没有信息不对称——不会产生真正的差异观点。对比 L1 反向者看得更有效——至少 L1 反向者可以从不同视角解读同一组宏观数据 |
| **裁判** | ❌ 6 维评分是确定性映射: >=35→强烈推荐, >=28→推荐, >=20→观察, <20→淘汰。不需要 LLM 再解读一遍 | ❌ 不读新数据 | ⚠️ 间接——CIO 可以直接消费 Scout 的评分而不需要裁判 | ❌ | **建议移除**。理由：Scout 输出的评分体系已经内建了判定逻辑。裁判的"推荐/观察/淘汰"是对 6 维分数的二次叙述——没有新增信息。CIO 可以直接消费 {code, total_score, valuation, top_risks} 的元组 |

**L2 诊断**：3 个角色缩为 1 个。**反方向题不需要独立 Agent——Scout 的自带评分模板 + 交叉验证规则引擎覆盖了原本反向者和裁判的全部功能。** 只有一种情况反向者有不可替代的价值：Scout 遗漏了冷门好公司。但这种冷门公司 Scout 自己也扫不到（缺少小盘数据源），反向者也扫不到——增加一个 Agent 不解决数据源问题。

#### L3 组合构建

| Agent | 不可替代性 | 专有信息 | 决策杠杆 | 判定 | 分析 |
|-------|----------|---------|---------|------|------|
| **分析师** | ✅ 唯一逐持仓评估安全边际的角色 | ✅ 唯一同时看 Tier1 报告+PE 分位+敞口数据的角色 | ✅ 直接决定 CIO 对每只持仓的理解 | ✅ | **必须存在**。它是 Tier1→CIO 的关键翻译层。当前问题：(1)Tier1 匹配只有 9/36→先修查询。(2) 它当前看不到 L1 裁判结果→修管道 |
| **策略师** | ✅ 唯一从组合视角挑战视图的角色 | ✅ 唯一用集中度工具+敞口矩阵做计算的角色 | ⚠️ 不输出操作建议，是诊断 | ⚠️ | **审慎保留**。存在价值："分析师推了 5 只加仓全在科技，集中度要到 40%"——这种聚合风险只有它能看到。但不输出操作建议意味着它的影响力是间接的——CIO 可以选择无视它的诊断 |
| **侦察兵** | ❌ "组合缺口"的发现可以由分析师（看哪些行业/风格缺失）+策略师（看集中度决定缺口方向）两位覆盖 | ❌ 只看持仓+L2 候选，不读 Tier1 也不调工具 | ❌ | ❌ | **建议移除**。侦察兵的输出"组合在新能源方向的缺口"本身不是可操作的——它没有工具去查新能源行业有什么好公司（那是 L2 Scout 的活）。如果 L2 已经覆盖了 L1 的 Go 行业，侦察兵的"缺口"几乎全是重复推荐 |

**L3 诊断**：3 个角色缩为 2 个。侦察兵的角色本质是"建议L2该搜什么方向"——而这个方向已经从 L1 的 Go 行业里明确了。

#### L4 最终处方

| Agent | 不可替代性 | 专有信息 | 决策杠杆 | 判定 | 分析 |
|-------|----------|---------|---------|------|------|
| **CIO 初稿** | ✅ 唯一综合所有层级做决策的角色 | ✅ 唯一同时看到 L1+L2+L3+冲突报告+敞口的角色 | ✅ | ✅ | **必须存在** |
| **风险总监** | ⚠️ CIO 自己也能做风险检查（prompt 有集中度红线） | ⚠️ 看的数据和 CIO 一样（处方草稿+敞口） | ⚠️ 间接——CIO 终裁可以无视 | ⚠️ | **审慎保留**。风险总监和 CIO 共享同一套数据和推理框架——和 L2 反向者同样的问题，没有信息不对称。但保留的理由不同：CIO 做初稿时处于"构建"模式，风险总监做审查时处于"攻击"模式——心理框架不同。同一套数据、不同心态，这比 L2 反向者有价值 |
| **CIO 终裁** | ✅ 唯一终裁权 | ❌ 不读新数据 | ✅ | ✅ | **必须存在** |

#### 实际 Agent 数量结论

```
原 LangGraph 12 个 Agent 节点
↓ 经过目的验证
claude_advisor: 8 个 Agent 节点 + 辩论循环 + 交叉验证

移除:   L2-反向者（Scout自带评分+规则引擎替代）
        L2-裁判   （6维评分确定性映射替代）
        L3-侦察兵（分析师+策略师覆盖其功能）
保留:   其余 8 个
```

移除的理由不是"简化"，而是**被替代的 Agent 没有信息不对称**——和最保留的 Agent 看到同一套数据，分歧只是 LLM 的随机性，不是真正的不同视角。

**L1 反向者之所以留下**：它和策略师看同样的宏观数据，但立场完全不同（看多 vs 看空）。而 L2 反向者和 Scout 看同样的工具结果——一个查询 `get_financial_summary` 返回 ROE=14.2，两个 Agent 解读不会有本质不同。一条数据，一种解读。
