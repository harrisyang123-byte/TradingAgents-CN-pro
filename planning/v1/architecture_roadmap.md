# 交易智能体系统 (TradingAgents-CN) 架构演进蓝图 v2.0

**版本**: v2.0
**日期**: 2026-05-30
**状态**: ✅ 全部11个维度已实现 (P0-P4 完成于 2026-05-30)
**定位**: 根据用户资金和投资目标，给出最完整的整体投资建议

---

## 1. 终极目标

> 根据用户的资金和投资目标，输出**可执行的整体投资建议**，覆盖：每只持仓的操作（买/卖/持 + 目标价 + 仓位）、行业配置指引、资金分配方案、执行时机、风险诊断、持续跟踪。

系统定位：**个人专属理财顾问**，不是"单只股票分析工具"。

---

## 2. 完整投资建议的 10 个维度

按依赖关系分五层优先级：

```
🥇 P0 — 地基（并行推进）
  1. Tier 1 个股全覆盖  — 每只持仓都有深度研报打底
  2. 敞口引擎           — 基金拆成底层股票，计算真实行业/个股敞口

🥈 P1 — 覆盖
  3. 行业全量覆盖       — 每个持仓行业都有 go/nogo 判断
  4. 存量 vs 增量拆分   — 调现有持仓 vs 买新标的，两条独立分析线

🥉 P2 — 执行
  5. 资金分配框架       — 全局资金约束下，处方之间不打架
  6. 时机条件 + 条件触发 — 立刻做 vs 等回调到 X 元再做

🏅 P3 — 风控
  7. 相关性/集中度风险   — 会不会一起崩？单票/单行业红线
  8. 情景压力测试       — 如果关税/加息/衰退发生，组合会怎样？

🏁 P4 — 持续
  9. 反馈闭环           — 历史处方执行了吗？结果如何？从错误中学习
 10. 再平衡机制         — 定期调仓还是机会触发？
 11. 现金管理           — 空仓资金怎么处理（货基/逆回购）？
```

---

## 3. 各维度详解

### P0-1：Tier 1 个股全覆盖

**现状**：
- 股票分析 (`TradingAgentsGraph`)：完整，有 batch 接口（`POST /api/analysis/batch`，max 10）
- 基金分析 (`FundAnalysisGraph`)：完整，和股票共用 `analysis_reports` 表
- 但 36 只持仓中仅 3 只有 Tier 1 报告，33 只"裸跑"
- 基金报告能写入、能被 `_prepare_tier1_reports()` 读到，但 **AdvisorGraph 全链路只用股票工具**，基金报告从未注入 agent prompt

**动作**：
- a) 用现有 batch 接口，分 4 批把 33 只持仓的 Tier 1 分析跑完
- b) 修复基金 Tier 1 → AdvisorGraph 的数据注入链路（让 `_prepare_tier1_reports()` 的基金数据真正进入 prompt）
- c) 基金不再需要独立分析 pipeline——改为数据源角色，产出重仓股 + 行业分布 + 净值走势，喂给敞口引擎

**技术**：`app/services/simple_analysis_service.py`、`app/routers/analysis.py`、`app/services/portfolio_advisor_service.py`

---

### P0-2：敞口引擎（从旧蓝图阶段三提升）

**现状**：Tier 2 看持仓只看表面——"你持有基金 B 20%"，但不知道基金 B 重仓了哪些股票。如果直接持股 + 基金底层持股重叠，系统感知不到。

**动作**：
- a) 实现 `ExposureEngine`：读取基金季报重仓股，按权重拆解为底层股票敞口
- b) 合并直接持股敞口 + 基金穿透敞口 → 真实行业/个股敞口矩阵
- c) 定义红线规则：单票 ≤ 15%、单行业 ≤ 30%、单基金 ≤ 20%
- d) 敞口数据作为 Tier 2 分析的**前置输入**，替代当前"只看表面持仓"的逻辑

**技术**：新建 `app/services/exposure_engine.py`，依赖 `fund_nav_cache` + AKShare 基金持仓 API

**依赖**：Tier 1 全覆盖（需要基金季报数据），可同步推进

---

### P1-3：行业全量覆盖

**现状**：CIO 只出 5-8 条精选处方，20 个行业中有 14 个无操作指引。openspec `full-portfolio-coverage` 已规划但未开始。

**动作**（对应 openspec `full-portfolio-coverage` 6 slices）：
- a) L1 输入从"市场扫描"变为"持仓行业列表 + 用户目标"，逐行业 go/nogo
- b) 轻量评估（light）覆盖全部持仓行业，深度辩论（deep）覆盖 ≤5 个高分歧行业
- c) `industry_coverage` 一次全量写入，废弃 `planned` 状态

**技术**：`market_strategist.py`、`contrarian.py`、`macro_judge.py`、`advisor_graph.py`、`Analysis.vue`

**依赖**：敞口引擎（需要真实行业敞口数据来判定 go/nogo）

---

### P1-4：存量 vs 增量拆分

**现状**：36 只持仓 + AI 推荐新标的混在一起处理。但这是两类本质不同的问题：
- **存量体检**：持有/加仓/减仓/清仓——需与现有成本、盈亏状态挂钩
- **增量探索**：新进入机会——需回答"为什么现在"和"替代谁"

**动作**：
- a) Tier 2 分析拆为两条独立线：存量诊断 + 增量探索
- b) 存量诊断输出：每只持仓的操作建议 + 理由（含成本/盈亏上下文）
- c) 增量探索输出：候选标的 + 入场条件 + 替代哪只现有持仓
- d) CIO 终裁时合并两条线的结论

**技术**：新建 `app/services/portfolio_audit_service.py`，改造 `cio.py` prompt

**依赖**：Tier 1 全覆盖（存量诊断需要个股研报）

---

### P2-5：资金分配框架

**现状**：CIO 输出"减 A 到 2%，买 B 到 5%"，但没有全局资金约束。如果 20 个行业都要求操作，钱从哪来、去到哪？处方之间可能相互矛盾。

**动作**：
- a) 定义全局资金约束模型：总资产、可用现金、单票/单行业上限
- b) 处方生成时带入资金约束，CIO 必须在约束内分配
- c) 输出"资金来源-去向"配对表

**技术**：改造 `cio.py` prompt + 新增 `CapitalConstraint` 模型

**依赖**：敞口引擎（需要真实敞口才能定约束）、存量 vs 增量拆分

---

### P2-6：时机条件 + 条件触发

**现状**：处方只有 `urgent/important/optional` 优先级，没有时间框架。"现在立刻减仓" vs "等回调到 X 价位再建仓"是本质不同的操作。

**动作**：
- a) 处方新增 `timing` 字段：`immediate` / `conditional` / `scheduled`
- b) `conditional` 处方带触发条件（价格阈值、事件、技术指标）
- c) 前端展示：区分"立即执行"、"条件触发（等待中）"、"定期再平衡"

**技术**：改造 `cio.py` 输出 schema + `DecisionCard.vue`

**依赖**：资金分配框架（时机和资金是硬币两面）

---

### P3-7：相关性/集中度风险

**现状**：没做。36 只标的是否高度同向？不知道。

**动作**：
- a) 基于敞口引擎的底层股票敞口，计算真实行业集中度
- b) 计算持仓间的历史相关性（价格 / 行业 / 因子）
- c) 超标时在处方中标注风险警告

**技术**：`ExposureEngine` 输出 → `RiskDirector` 消费

**依赖**：敞口引擎

---

### P3-8：情景压力测试

**现状**：没做。

**动作**：
- a) 预设情景：关税升级、人民币贬值 10%、美债利率 +200bp、A 股流动性危机
- b) 基于历史回测估算每个情景下的组合回撤
- c) CIO 处方中包含"最脆弱环节"诊断

**技术**：新建 `app/services/stress_test.py`

**依赖**：敞口引擎

---

### P4-9：反馈闭环

**现状**：每次分析从零开始，不参考历史处方，不评估执行结果。

**动作**（吸收旧蓝图阶段三#2 方法论注入）：
- a) `portfolio_advice` 增加处方执行状态 + 回顾评估字段
- b) 离线 Agent 定期回看历史预测准确率，自动微调 Prompt
- c) 新分析开始时注入上次处方摘要 + 执行情况

**技术**：`portfolio_advice` 表结构扩展 + 离线 `MethodologyAgent`

---

### P4-10：再平衡机制

**现状**：没有定义。系统不知道用户的调仓频率偏好。

**动作**：
- a) 支持用户设定：定期再平衡（季度/半年）或机会触发
- b) 定期模式下，系统在到期时主动提示
- c) 机会触发模式下，持续监控条件，满足时推送

---

### P4-11：现金管理

**现状**：没做。

**动作**：
- a) 组合层面展示现金占比
- b) 建议闲置资金配置（货基/逆回购）
- c) 在建仓/减仓建议中考虑现金缓冲
