# v4 自进化投研优化循环协议（Self-Evolving Optimization Loop）

> **文档性质：这是一台"引擎"，不是一张"清单"。**
> 它不预先列出所有优化项（那会变成一次性死命令、做完即止）。它定义一套**可重复运行的循环**：
> 让任何一次 AI 运行都能自己**发现**当前最痛的"浅尝即止"的洞 → **加深实施** → 用**超级投资人标准检查闭环** → **沉淀** → **继续下一轮**。
>
> backlog 不在本文档里预列，而是在运行时的状态文件 `data/v4/_loop/optimization_state.json` 里**动态生长**。
>
> **唯一真源**：本协议 + 状态文件 + 标尺库（Part 2）。方法论铁律仍以 `AGENTS.md` / `planning/v4/project-master-prompt.md` 为准。

---

## Part 0 — 北极星（每轮循环开始前必读一遍，一切判断回到这条）

> **让用户持久盈利（绝对收益），靠的是真正执行真实世界超级投资人的最佳实践——而不是"看起来执行了"。**

衡量任何一次优化是否值得做，只有一个问题：
> **它有没有让我们的系统，从"嘴上引用某条投资理念"变成"流程里真的做到了"？**

这条北极星把用户两个核心痛点焊死在一起：
1. **真实世界最佳投资实践**（超级投资人怎么做 → Part 2 标尺库）
2. **浅尝即止的毛病**（22+ 个 agent 角色，但方法论支撑不足，导致每个洞都挖一铲就走 → Part 5 深度闸门）

## Part 1 — 为什么是 Loop 而不是死清单（设计哲学）

### 1.1 死清单的失败模式（用户明确拒绝的）
- 一次性把"该优化的 50 项"列出来 → 做完即止 → 下次不知道该干嘛 → 系统停止进化。
- 列清单的人（现在的我）认知有限，列出来的多半是"我现在想得到的"，恰恰漏掉"做的过程中才暴露的洞"。
- 清单是静态的，市场和系统是动态的——昨天补的洞，今天可能又浅了。

### 1.2 Loop 的本质（借鉴 Microsoft SkillOpt 的训练纪律）
SkillOpt 把 agent 的 skill 文档当"可训练权重"，用深度学习的纪律迭代优化。我们借它**五条核心纪律**（不部署其代码，只用其方法）：

| SkillOpt 概念 | 本协议对应 | 作用 |
|---|---|---|
| Rollout（前向） | **DISCOVER 发现**：跑一遍系统/复看产物，暴露最痛的洞 | 让问题自己浮现，不靠预列 |
| Reflect（反向/梯度） | **DIAGNOSE 诊断**：这个洞违反了哪条超级投资人实践、为什么浅 | 找根因不打补丁 |
| Aggregate + Select（梯度聚合+裁剪） | **聚焦单点**：每轮只攻 1 个最痛的洞（learning rate=1~2） | 防一次改太多过拟合 / 浅尝 |
| Update（优化器 step） | **IMPLEMENT 实施**：真把这个洞挖到底 | 深做一处 > 浅做十处 |
| **Validation Gate（验证闸门）** | **GATE 检查闭环**：critic 真打分，提分才接受，否则回退 | **防自欺的核心** |
| Slow update / Meta skill（跨轮记忆） | **CONSOLIDATE 沉淀**：写进 skill 保护区 + 状态文件 | 让下一轮站在这一轮肩上 |

**核心信念**：与其一次列 50 项浅浅做，不如每轮深挖 1 项，做满 50 轮——每轮都有 gate 把关不退化，50 轮后系统真的不一样了。

## Part 2 — 衡量标尺库：超级投资人"真执行" vs "浅尝即止"

> 这是 DISCOVER 阶段的"探照灯"。每轮循环用它逐条扫描系统，问：**这条实践，我们是真做到了，还是只是嘴上引用？**
> 找到差距最大（"嘴上有、流程无"）的那一条 = 本轮要攻的洞。

### 2.1 巴菲特 / 芒格（Buffett / Munger）

| 实践 | ✅ 真执行（系统该怎么做） | ❌ 浅尝即止（失败模式） |
|---|---|---|
| **能力圈** | 每个标的/行业显式标注"认知边界"：哪些环节我们看得懂、哪些看不懂不碰，看不懂的降 confidence | 什么都敢分析、什么都给目标价，从不承认"这个我们看不透" |
| **护城河量化** | 用五力+卡位+ROIC>WACC 的**持续性与趋势**量化护城河"宽度"和"在变宽还是变窄" | 一句"有品牌/技术护城河"就完事，不量化、不看趋势 |
| **安全边际** | 买点 = 内在价值 ×(1−margin)，且内在价值有 DCF/可比推导链 | 给个买点，但没有内在价值锚，安全边际是拍的 |
| **逆向思考 (invert)** | 先建"死亡清单"：什么情况下这笔会亏光本金，再反推规避 | 只论证看多逻辑，不先想"怎么会死" |
| **股东盈余 / FCF** | 用 owner earnings / FCF（剔除维持性 capex）而非净利润判断赚钱能力 | 只看 PE / 净利润增速 |
| **多元思维格栅** | 跨学科交叉（供应链/博弈论/心理学/会计）验证同一结论 | 只用财务单一维度 |

### 2.2 段永平（Duan Yongping）

| 实践 | ✅ 真执行 | ❌ 浅尝即止 |
|---|---|---|
| **商业模式优先** | 先问"这是不是一门好生意"（现金流/复购/定价权/规模效应），再谈价格 | 只看"估值便宜"，不问生意本身好不好 |
| **Stop doing list** | 系统显式维护"不做什么"：不博周期股价差/不碰看不懂的/不追高关注度热点 | 什么机会都想抓，没有"不做清单" |
| **管理层与企业文化** | 评估管理层资本配置历史（分红/回购/并购质量），把"人"算进去 | 完全不看管理层，只看数字 |
| **做对的事 + 把事做对** | 区分"方向对不对"(选股逻辑) 和"执行到不到位"(深度)，两层都查 | 方向对就以为做完了，不查执行深度 |

### 2.3 霍华德·马克斯 / Serenity（Marks / 二阶思维 + 周期 + 风险）

| 实践 | ✅ 真执行 | ❌ 浅尝即止 |
|---|---|---|
| **二阶思维 / 预期差** | 问"市场已 price-in 了什么，我和共识的差异在哪"，差异即 alpha 来源 | 跟随共识，把"大家都看好"当买入理由 |
| **周期定位** | 判断当前在周期哪一段（渗透率 S 曲线/库存周期/估值分位），不线性外推 | 把当前增速线性外推到永远 |
| **风险 = 永久损失本金** | 区分"波动"与"永久损失"，重点防后者（基本面双杀/卡位丧失） | 用 beta/波动率当风险，忽略永久损失 |
| **无人知晓的瓶颈（紫苏叶）** | 上溯产业链找"缺了它整个链转不动"的低关注度卡位，靠专利/客户名单碎片演绎 | 只买大家都知道的龙头，或用研报验证（研报=已知=反了） |

### 2.4 达里奥（Dalio）

| 实践 | ✅ 真执行 | ❌ 浅尝即止 |
|---|---|---|
| **原则化 + 极度求真** | 每个判断可证伪（写明"看到 X 就证明我错了"）+ 留痕 + 复盘 | 拍脑袋下结论，不留可证伪信号，错了也查不出 |
| **"What am I missing?"** | 主动搜集反面证据、列盲区清单，对抗确认偏误 | 只找支持自己的证据 |
| **真分散 / 相关性** | 理解持仓间相关性，真分散（不同驱动因子）而非堆数量 | 买 10 只同赛道股，自以为分散了 |

### 2.5 费雪 / 李录 / 格雷厄姆（Fisher / Li Lu / Graham）

| 实践 | ✅ 真执行 | ❌ 浅尝即止 |
|---|---|---|
| **闲聊法 (scuttlebutt)** | 用客户名单/产能地图/上游矿源/专利碎片做一手演绎（我们的五因子模型正是这个） | 只读卖方研报二手结论 |
| **错杀龙头识别** | 区分"被错杀的卡位龙头"(中际旭创¥88案) vs "基本面双杀"，不按 PE 分位一刀切 | 看 PE 分位高/市值大就一刀切排除，错过 11 倍 |
| **deep value + 成长** | 好公司 × 好价格 × 好未来三维同时看 | 只看便宜（价值陷阱）或只看成长（透支） |

> **标尺库是活的**：循环运行中若发现某条超级投资人实践没被收录，CONSOLIDATE 阶段应补进本表（Part 2 也会进化）。

## Part 3 — 循环机制（6 阶段 + 角色分工）

```
        ┌──────────────────────────────────────────────────────────────┐
        │                    一轮循环 (one iteration)                    │
        │                                                                │
   ①DISCOVER ──▶ ②DIAGNOSE ──▶ ③IMPLEMENT ──▶ ④GATE ──┬──▶ ⑤CONSOLIDATE │
    发现最痛洞      诊断根因       深挖到底       闸门检查 │      沉淀          │
        ▲                                          │ FAIL  │              │
        │                                          └───────┘ 回退/重做      │
        │                                                        │         │
        └────────────────────── ⑥CONTINUE ◀──────────────────────┘         │
                              读状态文件，开下一轮                            │
        └──────────────────────────────────────────────────────────────┘
```

### ① DISCOVER（发现）— 让洞自己浮现，不预列
**谁做**：`v4-chief-investment-officer`（CIO）主导 + 主 agent 协助取证。
**怎么做**：
1. 读北极星（Part 0）+ 标尺库（Part 2）+ 状态文件（已做过的不重复）。
2. 用 CIO 五维拷问（可信/能用/连得上/会学/值得）+ 标尺库逐条扫描，**抽样真看 2~3 个真实产物**（如 `data/v4/stocks/*.json`、行业 verdict、某条选股链），不空谈。
3. 输出**候选洞清单**（3~5 个），每个标注：违反了哪条超级投资人实践 + 浅尝程度 + 对"用户持久盈利"的伤害。
4. **Select（裁剪到 1 个）**：按"不做就不可信 > 做了更漂亮"排序，**本轮只锁定 1 个最痛的洞**（learning rate = 1）。

> **铁律**：DISCOVER 必须基于**真看产物**，禁止凭印象空想洞。看到的具体证据要写进状态文件。

### ② DIAGNOSE（诊断）— 找根因，不打补丁
**谁做**：CIO + 主 agent。
**怎么做**：问到底"为什么浅"——是缺方法论 skill？缺 agent 角色？agent 有但 prompt 没要求深做？还是字段有但没人填？根因决定 ③ 怎么修（改 skill / 新建 agent / 改 .md / 改代码）。
> 对照 AGENTS.md §7 MECE 反偷懒铁律：某维度无 agent 对应 → 必须新建，不能凑合。

### ③ IMPLEMENT（实施）— 深挖到底
**谁做**：主 agent（或 development-agent）。
**怎么做**：只攻这 1 个洞，但**挖到底**（Part 5 深度闸门定义"到底"）。可能产出：新 skill / 改 agent .md 加强制方法论 / 新建 subagent / 改代码字段 / 补一条 verified 数据链。
> 改了代码/prompt 必须同步 AGENTS.md + README（§0 文档即代码契约）。

### ④ GATE（检查闭环）— 验证闸门，防自欺的核心
**谁做**：`v4-investor-critic`（真 spawn，禁主 agent 自评）。
**怎么做**：对比"改之前 vs 改之后"，回答：
- 这个洞真的被填上了吗？还是换了个地方继续浅？
- 通过了 Part 5 深度闸门 rubric 吗（逐条打分）？
- 有没有引入新的浅尝/断层/孤儿（§9 孤儿模式）？
**判定**：
- **ACCEPT**（提分且过深度闸门）→ 进 ⑤ 沉淀。
- **NEEDS_CHANGES**（没提分或仍浅）→ **回退**，带 critic 反馈重做 ③（loop_to）。第 2 次仍 fail → 状态文件标 `stuck`，换洞或升级求助用户。

### ⑤ CONSOLIDATE（沉淀）— 让下一轮站在这一轮肩上
**谁做**：主 agent。
**怎么做**：
1. 把验证通过的方法论写进对应 `skills/v4-*/SKILL.md`（含 `<!-- USER_CORRECTION -->` 保护区，见 Part 6.3）。
2. 更新状态文件：本洞标 `done`、记录证据/前后对比/critic 分数。
3. 若发现新洞，**追加进状态文件 backlog**（backlog 在此生长）。
4. 更新 `rerun-memory.md`（跨会话记忆）。
5. git commit + push（一个洞一个 commit，可追溯、可回退）。

### ⑥ CONTINUE（继续）— 开下一轮
读状态文件，回到 ①。直到状态文件里**找不到"不做就不可信"级别的洞**（系统达到"可信赖投资伙伴"基线），循环转入维护态（仅在新产物出现/市场变化时触发）。

### 角色分工总表
| 阶段 | 主责 | 工具 | 产物 |
|---|---|---|---|
| ① 发现 | `v4-chief-investment-officer` | Read（真看产物） | 候选洞 + 锁定 1 个 |
| ② 诊断 | CIO + 主 agent | Read | 根因 + 修法 |
| ③ 实施 | 主 agent / development | 全部 | 代码/skill/.md 改动 |
| ④ 闸门 | `v4-investor-critic`（真 spawn） | Read | ACCEPT/NEEDS_CHANGES + 打分 |
| ⑤ 沉淀 | 主 agent | Write/Shell(git) | skill+状态文件+memory+commit |
| ⑥ 继续 | 主 agent | Read | 读状态开下一轮 |

> **可用 `subagent` 工具的 loop_to 实现 ③↔④ 自循环**：development 实施 → critic 闸门，trigger="NEEDS_CHANGES" loop 回 development，max_iterations=2。

## Part 4 — 持久化状态文件（loop 的 runtime_state，backlog 在此生长）

> 路径：`data/v4/_loop/optimization_state.json`。这是循环的"记忆"，让任意一次 AI 运行都能**接上上一轮**继续，而不是从头来。
> backlog **不在协议文档里预列**，而是在这里由 DISCOVER 阶段动态生长、CONSOLIDATE 阶段动态收割。

### Schema
```jsonc
{

    "protocol_version": "1.0",
    "north_star": "让用户持久盈利——真执行超级投资人实践，而非看起来执行",
    "iteration_count": 0,            // 已完成多少轮
    "last_run": "2026-06-17T00:00:00Z",
    "phase": "idle",                 // idle|discover|diagnose|implement|gate|consolidate
    "learning_rate": 1,              // 每轮锁定几个洞(默认1，防浅尝)
    "status": "running"              // running|maintenance(无高优洞)|stuck

  // 本轮正在攻的洞(单点聚焦)
  "active_hole": {

    "fix_plan": "新建skills/v4-moat-quantification + competitive.md加强制引用",
    "phase": "implement",
    "gate_history": []              // [{attempt:1, verdict:"NEEDS_CHANGES", score:72, feedback:"..."}]
  },

  // 已发现但还没轮到的洞(DISCOVER追加，按优先级排队，不预列死)

    // {id, title, violated_practice, shallow_score, harm_to_profit, priority:"must|should|could", discovered_at}
  ],

  // 已填上的洞(可追溯，防重复挖)
  "done": [
    // {id, title, before, after, critic_score, skill_consolidated, commit, completed_at}
  ],

  // 卡住的洞(2次gate失败，需换洞或求助用户)
  "stuck": [
    // {id, title, why_stuck, escalate_to_user:true}
  ],

  // 跨轮优化器记忆(对应SkillOpt meta-skill：什么修法有效/无效)
  "meta_memory": {
    "what_worked": [],   // ["深做一处护城河量化skill后，相关股critic分+8"]

```

### 使用规则
- **每轮开始**：读本文件 → 看 `active_hole` 是否未完成（接着干）或为空（从 backlog 取最高优，或 DISCOVER 找新洞）。
- **backlog 生长**：DISCOVER/CONSOLIDATE 发现新洞就 append，**不一次性填满**（那就退化成死清单了）。
- **done 防重复**：DISCOVER 前先查 done，已填的洞不重挖（除非复发——复发记进 meta_memory.what_failed）。
- **stuck 升级**：同一洞 2 次 gate 失败 → 移入 stuck + `escalate_to_user:true`，下次面对用户时主动汇报求决策。

## Part 5 — 深度闸门 rubric（"浅尝即止"检测器）

> GATE 阶段用它给"改后产物"逐条打分。**任何一条不达标 = 仍是浅尝 = NEEDS_CHANGES 回退。**
> 这是把"浅尝即止"从模糊感觉变成可检验标准的核心。

### 5.1 浅尝即止 5 大特征（命中任一即判浅，shallow_score +1）
1. **一句话定性，零量化**：说"有护城河/景气度高/估值合理"但没有数字、趋势、推导。
2. **套话填字段**：schema 字段填满了，但每个都是放之四海皆准的废话，换个股票也成立。
3. **断层不闭环**：分析了 A，但没回答"所以呢"——瓶颈分析没落到买哪只，行业 go 没落到首选哪只。
4. **拍脑袋数字**：给了买点/目标价/配比，但没有 verified 数据 + 推导链（违反 RULE-DATA-VERIFIED）。
5. **不可证伪**：结论没有"看到 X 就证明我错了"的反向信号，错了也查不出（违反达里奥极度求真）。

### 5.2 深度达标 5 条（全部满足才算"挖到底"，才 ACCEPT）
1. **可量化**：关键论断有数字 + 趋势（变宽/变窄、加速/减速）+ 同行/历史对比。
2. **可证伪**：每个核心判断配 ≥1 个可监控的反向信号（绝对阈值）。
3. **闭环到行动**：分析最终落到"用户今天该买什么/买多少/什么价买/什么价跑"。
4. **数据 verified**：所有数字有来源 URL（≥3 独立源 for TAM 类）或标 missing，绝不编造。
5. **方法论显式**：用了 Part 2 标尺库里 ≥1 条超级投资人实践，且在产物里**显式写出"用了哪条、怎么用的"**（不是暗用）。

### 5.3 GATE 打分卡（critic 输出）
```
深度闸门评分（满分100，<85=NEEDS_CHANGES）：
- 可量化         /20
- 可证伪         /20
- 闭环到行动     /20
- 数据verified   /20
- 方法论显式     /20
浅尝特征命中：[列出命中的1-5项]
判定：ACCEPT / NEEDS_CHANGES
回退反馈：[若NEEDS_CHANGES，具体指出哪里还浅、该怎么深]
```

## Part 6 — 启动协议（AI 每次跑起来怎么接上这个循环）

### 6.1 触发口令（用户说任一即进入循环）

- 或用户颁布"整体优化任务"时，默认按本协议跑。

### 6.2 单次运行的标准动作（一轮 = 一次 git commit）
```
1. 读 planning/v4/self-evolving-optimization-loop.md（本协议）
2. 读 data/v4/_loop/optimization_state.json（状态）
3. 若 active_hole 未完成 → 接着干；否则 DISCOVER 找新洞(或从 backlog 取)
4. 走 ②→⑥ 六阶段，critic 真 spawn 把关
```

## Part 7 — 防自欺铁律（loop 最容易烂掉的地方，重点防）

循环最大的风险是**自己骗自己**：假装发现了洞、假装填上了、critic 走过场。以下铁律防退化：

1. **DISCOVER 必须真看产物**：禁止凭印象空想洞，看到的具体证据（文件名+字段+原文）写进状态文件，可被复核。
2. **GATE 必须真 spawn critic**：禁止主 agent 自评打分绕过（对齐 AGENTS.md §0bis）。critic 看不到"前后对比"就不能判 ACCEPT。
3. **单点聚焦，禁批量浅做**：learning_rate 默认 1。想一次改 5 个 agent.md → 触发 meta_memory.what_failed 里记录的反模式，禁止。
4. **提分才接受，否则回退**：没有"改后比改前在深度闸门上真提分"的证据，一律 NEEDS_CHANGES，绝不"算了先这样"。
5. **复发要诚实记账**：填过的洞又浅了，记进 meta_memory.what_failed + 重新入 backlog，不假装没发生。
6. **卡住要升级用户**：2 次 gate 失败的洞进 stuck，主动告诉用户"这个我搞不定，需要你决策"，不无限空转。
7. **不为循环而循环**：当找不到"不做就不可信"级别的洞，诚实进入 maintenance 态，不硬造洞刷 iteration_count（那也是一种浅尝）。
8. **标尺库是锚不是装饰**：每轮至少有 1 个洞直接对应 Part 2 某条超级投资人实践，确保循环始终服务"真执行最佳投资实践"而非自嗨重构。
