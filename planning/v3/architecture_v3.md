# TradingAgents-CN 架构 v3

> 版本：v3.0  
> 状态：已确认（Grill 完成，2026-06-04）  
> 核心原则：以用户持久盈利为目标，信息粒度从粗到细，每层专注一个问题，辩论驱动质量。

---

## 设计哲学

**为什么这样设计？**

- 大型机构分工细是因为人的精力有限。AI 没有此限制，但专注仍然比全能更好——上下文越聚焦，判断质量越高。
- 信息粒度从宏观到微观：先知道该不该进场，再知道进哪个赛道，再知道选哪家公司，最后知道配多少钱。顺序颠倒必然产生矛盾。
- 辩论是核心价值：每层都有挑战者，避免单一视角的确认偏误。
- 风控是硬约束，不是建议：规则引擎事前拦截，不可绕过，不依赖 LLM 自觉。

---

## 常态化后台（独立于主流程）

### 数据层（实时）
- 市场情绪：北向资金、融资余额、涨跌比、涨跌停数
- PE 分位库：行业 + 个股历史估值分位（AKShare）
- 持仓数据：当前仓位、成本、盈亏、持仓时间
- 宏观经济指标：利率、PMI、CPI 等

### Tier1 研究库（公司研究引擎）
- **触发方式**：被 Step 1 行业层驱动（行业判 Go → 自动研究该行业主要公司）
- **不是**用户手动触发的独立工具
- **缓存**：7 天有效期，重大事件可手动强制刷新
- **内部结构**：四维分析师并行（基本面 / 技术面 / 宏观 / 情绪）→ Bull vs Bear 辩论 → 公司裁判
- **输出**：评级（买入/持有/卖出）+ 目标价 + 买入价格区间 + 风险提示

## 主流程（每次运行）

### Step 0：宏观层
**核心问题**：现在该冒险还是该保守？

| 项目 | 内容 |
|------|------|
| 输入 | 宏观经济数据 + 市场情绪（北向/融资/涨跌比）|
| 辩论 | 宏观策略师 vs 宏观反向者（2轮）→ 宏观裁判 |
| 输出 | risk-on/off + 股票总仓位上限 + 现金下限 |
| 约束 | 所有下游层的仓位分配不得突破此上限 |

---

### Step 1：行业层
**核心问题**：钱该放在哪个赛道？

| 项目 | 内容 |
|------|------|
| 输入 | Step 0 结论 + 行业景气数据 + 估值（PE历史分位）+ 新闻研报 + AKShare硬数据 |
| 并行 | 每个行业独立 spawn 行业研究员 |
| 行业内辩论 | Strategist vs Contrarian（固定 2 轮）→ 行业裁判 |
| 跨行业辩论 | 所有行业裁判结论汇总 → 跨行业权重辩论（1 轮）→ 行业总裁判 |
| 缓存 | 7 天有效期，未过期直接复用，跳过重新辩论；可手动强制刷新 |
| 同时触发 | Tier1 研究库：对所有 Go 行业的主要公司启动研究（后台异步）|
| 输出 | 每行业 go_nogo + suggested_weight + reasoning |

**行业研究员的判断依据（双因子）**：
- 景气度：TAM / 渗透率 / 供需格局 / ROE 趋势 / 政策方向 / 资金流向 / 新闻研报
- 安全边际：PE/PS 历史分位（成长期行业不因 PE 高被否决，估值作调节因子）
- suggested_weight = 景气度 × 安全边际综合评分，受 max_industry_weight 红线硬约束

---

### Step 2：公司层 ‖ Step 3：组合层（并行）

#### Step 2：公司层
**核心问题**：Go 的赛道里选哪几家公司？

| 项目 | 内容 |
|------|------|
| 输入 | Step 1 Go 行业列表 + Tier1 研究库报告 + L2 Scout 新候选标的 |
| 流程 | Scout 在 Go 行业广撒网 → 读 Tier1 报告 → 行业内横向比较（Bull vs Bear，2轮）→ 公司裁判 |
| 输出 | 每个 Go 行业的候选标的排序 + 评级 + 目标价 |

#### Step 3：组合层
**核心问题**：现有持仓怎么处理，空间怎么腾？

| 项目 | 内容 |
|------|------|
| 输入 | 当前持仓 + Step 1 行业权重 + 敞口矩阵 |
| 并行 | 持仓分析师（逐只诊断）/ 策略师（整体敞口）/ Scout_L3（缺口识别）三者并行 |
| 辩论 | 三者结论汇总 → 组合反向者挑战（2 轮）→ 组合裁判 |
| 输出 | 建议减仓 / 清仓标的 + 释放空间 + 敞口风险说明 |

---

### Step 4：配仓层（PM）
**核心问题**：具体买多少、什么价、怎么买？

| 项目 | 内容 |
|------|------|
| 输入 | Step 1 行业配额 + Step 2 候选标的排序+评级+目标价 + Step 3 建议减仓标的+释放空间 |
| 辩论 | 激进 PM vs 保守 PM，对**整体配仓方案**辩论（2 轮）→ PM 裁判 |
| 注意 | PM 辩论是组合级（整体方案），不是逐股辩论（单股辩论已在 Step 2 完成）|
| 输出 | 减仓清单（卖什么 / 卖多少 / 建议卖出价）+ 买入清单（target_weight / 买入价格区间 / 分批策略）|

---

### Step 5：风控层（硬约束，规则引擎，非 LLM）
**不可绕过，违规打回 Step 4 重做。**

| 规则 | 说明 |
|------|------|
| 单股上限 | target_weight ≤ max_single_weight |
| 行业上限 | 行业实际配比 ≤ Step 1 suggested_weight |
| 总仓位上限 | 总仓位 ≤ Step 0 上限 |
| 现金下限 | 现金 ≥ Step 0 下限 |
| 黑天鹅缓冲 | 触发黑天鹅预警时，现金强制 ≥ 20% |

---

### Step 6：风险压测
**核心问题**：这个方案最坏会怎样？

| 项目 | 内容 |
|------|------|
| 输入 | Step 4 配仓方案 |
| 辩论 | 悲观 Risk Director vs 乐观 Risk Analyst（2 轮）→ 风控裁判 |
| 输出 | 市场下跌 20% 时最大回撤 + 黑天鹅触发条件 + 现金缓冲建议 |

---

### Step 7：CIO Final（终止递归，不再辩论）
**核心问题**：所有层的结论是否一致？矛盾在哪里？

| 项目 | 内容 |
|------|------|
| 输入 | 所有层裁判结论 |
| 职责 | 检查跨层矛盾 / 确认行业缺口 / 触发缺口侦察 / 最终确认或打回某层重做 |
| 输出 | industry_matrix（含缺口标注）+ 最终处方确认 + 矛盾说明 |
| 为什么不辩论 | CIO Final 是递归终止角色，加辩论会导致无限循环；质量由各层充分辩论保证 |

**CIO Final 不选股，不定个股权重，只做跨层矛盾裁决。**

```
  清仓：万科    → 目标 0%，9.5 元以上尽快执行，释放 ¥48,000

          第三批 2%（跌 10% 时）¥12,000

  当前方案在市场下跌 20% 时最大回撤约 18%
  现金缓冲 15%，可应对黑天鹅

【矛盾说明】（CIO Final 输出）
  科技行业配额 25%，公司层仅找到 14% 的合格标的
  缺口 11% 暂留现金，已触发补充侦察
```

## 与 v2 架构的核心差异

| 维度 | v2 | v3 |
|------|----|----|
| Tier1 触发 | 用户手动触发，孤立运行 | 被行业层驱动，结果存库供下游消费 |
| 个股研究时机 | 最先行（历史遗留） | 行业确定 Go 后才触发 |
| 执行顺序 | 完全串行 | Step 2+3 并行，行业研究员并行 |
| CIO 职责 | 自己选股、定个股权重、输出处方 | 只做跨层矛盾裁决，不碰个股 |
| PM 层 | 不存在 | 新增，专注组合配仓，激进 vs 保守辩论 |
| 风控 | L4 之后事后检验 | Step 5 事前硬拦截，规则引擎不可绕过 |
| Risk Director | 单角色 | 悲观 vs 乐观双角色辩论 |
| 行业研究缓存 | 无 | 7 天有效期 + 手动强制刷新 |
| 持仓录入行业分类 | 运行时 LLM 实时计算 | 录入时持久化到 paper_positions.industry |

## 开放问题（后续迭代）

- 行业缺口自动触发补充侦察（本次已纳入，CIO Final dispatch_scout）
- 权重归一化进一步合理性保证（当前：CIO Final 在 max_industry_weight 红线内裁量）
- 事件触发行业缓存失效（当前：手动强制刷新；后续：监听重大政策/财报事件）
- 用户自定义基准指数（当前：不设基准，以绝对盈利为目标）
- Tier1 覆盖范围自动扩展（当前：Go 行业主要公司；后续：候选标的动态扩展）
