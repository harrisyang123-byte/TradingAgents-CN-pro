# Proposal: Prescription Decision Cards

## Why

当前 CIO 处方输出为扁平 JSON（code, action, current_weight, target_weight, reasoning, risk_note），存在三个问题：

1. **缺少投资决策上下文**：用户看到"加仓茅台至 18%"，不知道这个判断基于什么——白酒行业处于什么生命周期？茅台护城河评级如何？当前估值在历史上是贵还是便宜？
2. **缺少价格锚点**：CIO prompt 完全没有使用价格数据（`get_stock_quotes` 返回的 price/pe/pb/ma20），处方只有"该不该买"没有"什么条件买"
3. **芒格约束留在自由文本**：max_loss_pct、five_year_view、bias_check 在 CIO prompt 中作为思维约束存在，但输出时被淹没在长篇叙述中，无法结构化展示

归根结底：**处方是一条投资决策，而当前它只是数据库里的一行 JSON**。缺少层层推导的可视化链路——行业判断 → 护城河评级 → 估值分位 → 风险量化。

**方案对比**：

- 方案 A（交易信号模型）：输出精简为 buy/sell/hold + target_price + stop_loss → 像量化策略的交易指令。优点：简单可执行。缺点：与"纯参谋"定位矛盾；没有解释 WHY；用户无法独立判断。
- 方案 B（投资论证模型）：每条建议附带完整论证报告（行业分析+公司分析+估值分析+风险评估）→ 像研报摘要。优点：信息完整。缺点：太长，用户面对 8 条建议 = 8 篇小作文；关键信息被淹没在文本中。
- 方案 C（决策卡片模型）：每条建议一张自包含卡片，分层信息——信任层（为什么信这个判断：L1 行业 + L2 护城河）+ 执行层（怎么行动：价格锚点 + 风险量化 + 时间视野 + 偏差检测）。优点：答案优先 + 支撑论据折叠；可扫读；IC 对标。缺点：字段多，后端改动大。

选择方案 C，理由：
1. 纯参谋定位下，决策卡片是"给你完整的判断依据让你自己决定"，而非"给你指令"
2. 对标业界 IC Insight Card 格式：结论句 + 3-4 条支撑论据 + 4 选项建议框架
3. 纵向卡片流可扫读，优先级排序后用户只需看前 3 条

**风险对冲**：
- 最可能失败的点：PE 分位数据管道——不同市场数据密度不同（A 股每日/BaoStock，港股季度/AKShare，美股年度/yfinance），CIO 拿到不同质量的数据可能产生不一致的输出质量 → 统一输出 schema，空字段显式标注原因（如 `pe_percentile_5y: null, pe_percentile_source: "unavailable_for_us"`）
- 预备方案：若 PE 分位计算不稳定（AKShare 接口变动、yfinance 限流），降级为仅使用 MA20 + 当前 PE 做定性判断

**Edge Case**：
- 新股/次新股（上市 < 1 年）无 PE 历史 → 跳过 PE 分位，标注"上市不足一年"
- 亏损企业（PE 为负）→ 不计算 PE 分位，改用 PB 分位或直接标注"亏损"
- 多市场混合组合（同时持有 A 股+港股+美股）→ 每只标的独立计算 PE 分位，不跨市场比较

## What

1. **PE 历史分位数据管道**：三市场统一接口，计算当前 PE 在历史区间的位置
2. **决策卡片 6 字段**：l1_context、l2_context、suggested_price、max_loss_pct、five_year_view、bias_check
3. **CIO prompt 增强**：注入价格/PE/MA 结构化数据，强制输出 6 字段
4. **前端决策卡片组件**：纵向卡片流替代扁平表格，分层信息展示
