# Exposure Engine — 敞口引擎

## Why

当前组合分析只看直接持仓，基金被当作黑盒处理。实际上：

- 基金本质是穿透层——每只基金重仓 5-10 只股票
- 组合里有 20 只基金 + 8 只个股，**实际敞口 = 个股 + 基金穿透后的底层股票**
- 不穿透会导致：看不到真实的行业集中度、个股过度暴露、基金经理赌注重叠

**目标**：基金持仓拆解 → 底层股票敞口 → 合并矩阵，让顾问看到真实的风险暴露面。

### 方案对比

| | A: 独立 pipeline（旧） | B: 数据源模式（新） |
|---|---|---|
| 基金分析 | 独立跑 Tier 1 → 报告 | 基金季度持仓拆解 → 底层股票敞口 |
| 顾问视角 | 看到"N 只基金，评级 X" | 看到"实际持有 78 只底层标的，前 10 权重 ≥ 60%" |
| 与敞口引擎关系 | 无 | 基金持仓 → 引擎输入 |
| 复杂度 | 两条独立管线 | 一条管线，基金做数据源 |

**选择 B**：基金分析的结论作为敞口引擎的数据输入，不再独立产出"基金买卖建议"。

### 风险对冲
- 最大风险：季度持仓数据滞后（基金季报延迟 15-20 个工作日）
- 预备方案：标注数据日期，超过 45 天标记为"stale"，提示用户手动更新
